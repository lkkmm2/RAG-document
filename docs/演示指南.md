# 演示指南（5 分钟版）

> 目标：在 5 分钟内让面试官看到"检索质量 + 引用可信 + 工程闭环"三件事，
> 而不是只看一个聊天框。

---

## 零、演示前 3 分钟准备

```powershell
# 终端 1：后端
.\.venv\Scripts\activate
python -m uvicorn docqa.api.main:app --port 8000

# 终端 2：前端
python -m streamlit run apps/web/app.py

# 终端 3（保险）：确认索引在位
python scripts/smoke_test.py
```

打开三个页面并排：

1. `http://127.0.0.1:8501` —— 前端问答
2. `http://127.0.0.1:8000/docs` —— Swagger（证明是接口驱动的）
3. `data/eval/reports/compare-*.md` —— 消融对比表（证明有评测）

**兜底**：如果环境起不来，直接打开 `data/eval/reports/demo-*.md` 讲工艺流程，
再打开 `docs/面试问答.md` 讲设计决策。**不要现场 debug。**

---

## 一、开场 30 秒：讲问题，不讲技术

> "学校/企业的规章文档有三个特点：长、结构化、还在更新。
> 直接问大模型会瞎编，微调成本又太高。这个项目做的是：
> 把文档切成能检索的块，先检索再回答，并且每条结论都能点回原文。"

打开前端，指一下左下角的"索引 1 篇 / 874 块"——**先给规模感**。

---

## 二、第 1 分钟：问一个能"看见引用"的问题

输入：

> 学生申请转专业需要满足什么条件？

预期：2-3 秒后出现流式回答，下方三张引用卡片（第 99 页 / 第 91 页 / 第 57 页）。

**话术**：
> 注意回答里的 `[1]`，它对应下面第一张卡片。点开能看到原文片段和页码。
> 引用不是排版，它是三件事：让用户能核对、让幻觉可检测、让效果可评测。

---

## 三、第 2 分钟：打开"显示检索过程"，讲四阶段

侧边栏勾选 **显示检索过程**，再问同一个问题。

展开面板，会看到四张表：向量召回 / BM25 召回 / RRF 融合 / 精排结果，每张表都带分数。

**话术（这是全场最重要的一段）**：
> 这里能看到四路结果的排序差异。向量召回排第一的，BM25 可能排第五；
> 融合之后会变；精排之后又会变。
> 为什么值得做四步？因为**召回上限和排序精度是两件事**：
> 我的评测里，四种配置的 recall@20 都是 0.95 —— 说明该捞到的都捞到了，
> 但 recall@4 从 0.70 到 0.90 差的就是"排序"。
> 精排把 MRR 从 0.54 提到 0.76，代价是 2.7 秒延迟——这就是我要权衡的地方。

---

## 四、第 3 分钟：问一个文档里没有的问题

关闭 debug，输入：

> 学校快递站在哪里？

预期：回答"文档中未提及"，没有引用卡片。

**话术**：
> 这一步是在测"它会不会硬编"。检索为空时我直接返回、不调用大模型——
> 既省钱，也避免模型开始编。评测集里专门放了 5 条无答案题算拒答率。

---

## 五、第 4 分钟：Agent 多步

切到 **Agent 多步**，输入：

> 这本手册里，学生违纪处分的种类有哪几种？

预期：出现"Agent 执行过程"折叠面板，能看到 `search_docs` → 思考 → `final_answer` 的步骤。

**话术**：
> Agent 是我手写的 ReAct 循环，没用框架。四个工程点：
> 终止条件不止步数（还有无进展检测）、工具失败要回灌给模型让它自纠、
> JSON 输出要容错解析、引用编号要全局重编号。
> 不用 LangChain 是因为这 100 行我更想自己能断点调试。

---

## 六、第 5 分钟：翻评测报告，收尾

打开 `data/eval/reports/compare-*.md`，指表格。

**话术**：
> 这张表是四组配置跑同一份 45 条评测集的结果。
> 我特意保留了"纯 BM25 比混合还好"这个反常结果——因为我的 gold 是用原文关键词对齐的，
> 天然偏袒字面匹配。这是评测方法的偏差，不是结论，所以下一步要补"同义改写"的测试样本。
> **能说清自己评测的局限，比报一个漂亮数字更重要。**

---

## 七、高频提问 & 应对

| 面试官问 | 你怎么答（一句话 + 展开） |
|---|---|
| 为什么不用 LangChain？ | 100 行能写清楚，想能断点调试；多 Agent 编排时我会换 LangGraph |
| 为什么不用向量数据库集群？ | 874 块，Chroma 零运维够用；百万级再换 Milvus |
| 精排 2.7 秒能上线吗？ | 不能，所以是已知瓶颈：压到 10 条候选、或 GPU、或换小模型 |
| 效果数据是真的吗？ | 全部可复现：`python scripts/eval.py --presets ...`，报告在 `data/eval/reports/` |
| 回答质量指标呢？ | 需要 API Key，命令是 `--with-answer`；没有 Key 时降级 Mock，我不会拿 Mock 数据当效果 |
| 数据泄露怎么办？ | Key 走 `.env` + gitignore；`/config` 接口有测试断言不返回密钥 |
| 如果文档有 1 万页？ | ingest 改异步任务队列，向量库换 Milvus，精排批量化/GPU |
| 你怎么知道切 400 字最好？ | 试过 200/400/600，配置一行可改；看 recall@4 和平均块长度 |

## 八、演示失败预案

| 情况 | 处理 |
|---|---|
| 端口被占用 | `--port 8001`，前端侧边栏不用改（它读 `DOCQA_API_URL`） |
| 模型没下载完 | 先演示 `/search`（不需要 LLM），或直接讲评测报告 |
| 没有 API Key | 明确说"现在是 Mock 模式，演示的是链路不是效果"，然后讲架构和评测 |
| 网络断了 | 全部本地依赖已缓存，只有 LLM 调用会失败 → 用 `/search` 演示检索 |
| 面试官要现场改参数 | 直接改 `configs/config.yaml` 的 `final_top_k` 或 `rerank.enabled`，重启后端即可 |

## 九、30 秒电梯版（电话/开场自我介绍用）

> 我做了一个中文文档问答系统，272 页的学校手册，切成 874 个块。
> 检索用向量加 BM25 双路召回、RRF 融合、Cross-Encoder 精排，
> 自建 45 条评测集做消融：精排把 recall@4 从 0.70 提到 0.90，MRR 从 0.54 到 0.76，
> 代价是 2.7 秒延迟，这是我知道的下一步优化点。
> 工程上是 FastAPI + Streamlit 分离、SSE 流式、Docker 部署、45 个离线测试。
